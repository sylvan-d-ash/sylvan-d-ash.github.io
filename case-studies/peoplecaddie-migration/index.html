PeopleCaddie · Application modernization

Modernizing without stopping product delivery.

I led PeopleCaddie’s phased migration from Objective-C to Swift and SwiftUI while the production application continued to evolve.

Challenge

Modernize without stopping the product.

PeopleCaddie had a large Objective-C codebase that needed safer long-term development and a path toward modern iOS technologies.

Rather than separating modernization into a wholesale rewrite, I planned it as a sequence of production changes. That kept the work compatible with ongoing delivery and made the order of migration an explicit technical decision.

Approach

A controlled path to the modern stack.

I led the migration and refactoring effort while continuing to support product delivery. Feature flags made it possible to introduce changes with controlled exposure rather than forcing every user onto new code at once.

  • Planned the migration and reviewed changes across old and new parts of the application.

  • Worked on application stability and performance alongside modernization.
  • Set up CI/CD pipelines using Bitrise and Fastlane.
Outcome

A more dependable way to change and release the app.

The work produced concrete safeguards around a long-lived codebase: feature flags supported controlled exposure, expanded automated and snapshot tests strengthened regression coverage, and Bitrise and Fastlane made the delivery pipeline more consistent.

Alongside stability, performance and refactoring work, those changes improved maintainability without separating modernization from ongoing product delivery. The result was not simply newer syntax—it was lower-risk change.

Takeaway

Migration is a delivery problem as much as a code problem.

The project required technical planning, incremental delivery, code review and judgment about sequencing. The migration worked because every step had to support both today’s production application and the system it was becoming.
