PeopleCaddie · Application modernization

From Objective-C to Swift and SwiftUI.

I led an incremental migration of a long-lived production application while continuing product delivery and reducing the risk of change.

Phased Production migration Built for controlled exposure
ProductPeopleCaddie

Challenge

Modernize without stopping the product.

PeopleCaddie had a large Objective-C codebase that needed safer long-term development and a path toward modern iOS technologies.

A wholesale rewrite would have concentrated risk and interrupted feature delivery. The migration instead needed to happen inside the production application, with careful decisions about which areas to change first.

Approach

A controlled path to the modern stack.

I directed the migration and refactoring effort while continuing to support product delivery. Feature flags made it possible to introduce changes with controlled exposure rather than forcing every user onto new code at once.

  • Planned the migration and reviewed changes across old and new parts of the application.
  • Expanded automated coverage and introduced snapshot testing.
  • Worked on application stability and performance alongside modernization.
  • Set up CI/CD pipelines using Bitrise and Fastlane.
Outcome

Safer change in a long-lived application.

The migration improved reliability and maintainability without separating modernization from ongoing product work.

Stronger testing and delivery automation made releases more consistent and reduced the risk involved in changing the existing system. The result was not just newer syntax—it was a more dependable way to evolve the product.

Takeaway

Migration is a delivery problem as much as a code problem.

The project required technical planning, incremental delivery, code review and judgment about sequencing. Modernization was most useful when each step made the system safer for the next one.
